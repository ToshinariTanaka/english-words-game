## 今回やったこと
- study-app 上部のモード名横にある `speakQuestionButton` のクリック処理を、専用の手動再生ハンドラーへ変更しました。
- 手動再生では既存の MP3 優先再生 → Web Speech API フォールバック処理をそのまま使い、ステータスに `手動再生：` を付けて自動読上げと区別できるようにしました。
- `speakQuestionButton` が存在しない環境でも初期化で落ちないよう、イベント登録を null チェック付きにしました。
- 上部行へ移動したスピーカーボタンが他要素にクリックを吸われにくいよう、ボタン自身に `position: relative` / `z-index` / `pointer-events: auto` を明示しました。
- 自動読上げOFFでも現在の問題がある限り手動スピーカーボタンが有効で、クリック相当の処理から MP3 再生が呼ばれることをテストで固定しました。

## 注意点
- ボタン表示は従来どおり `🔊` のみで、`type="button"`、`id="speakQuestionButton"`、`aria-label`、`title` は維持しています。
- 音声ステータス表示位置は、問題ID・レベル・学習履歴の下のまま維持しています。
- 手動再生は自動読上げON/OFFとは独立して利用できます。
- MP3が存在しない場合や再生に失敗した場合は、既存仕様どおり Web Speech API へフォールバックします。
