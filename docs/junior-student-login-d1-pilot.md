# Up塾・中学生英単語アプリ 学習管理（試験導入設計）

**状況：** 初期実装は GitHubの試験専用ブランチ `feature/junior-student-auth-d1-20261009` に限定。既存の生徒用公開サイト、管理者用Cloudflare Access、R2の共有1,691問、Render本番は現時点で変更しない。

## 目的と構成

- 問題・選択肢：既存の Cloudflare R2 `up-junior-words-data` を継続利用。
- 生徒IDとパスワード、セッション、学習履歴：専用 Cloudflare D1（新規）。
- 生徒画面：既存Cloudflare Pagesにログインパネルを追加する。初期段階は任意ログイン（未ログインでも従来の演習可）。
- 管理者画面：既存の別プロジェクト `up-junior-words-admin`、Cloudflare Accessで管理者だけを許可。
- 新しい生徒の自己登録は許可しない。生徒IDの発行、仮パスワードの再発行、無効化は管理者のみ。
- 生徒個人が別生徒の学習記録を閲覧するAPIは作らない。

## 決定済みの基本仕様

| 項目 | 現状の試験仕様 |
|---|---|
| 生徒ID | 英数字・ハイフン4〜24文字、英字は大文字に正規化（例 U0001） |
| 初期パスワード | サーバーで生成した20文字、管理者に一度だけ表示 |
| 初回操作 | 生徒が仮パスワードを変更（12〜128文字） |
| 保存方法 | PBKDF2-SHA256 600,000回＋利用者別の16バイトsalt |
| 生徒セッション | 14日間有効、Secure / HttpOnly / SameSite=Strict Cookie |
| パスワード再発行 | 管理者のみ、再発行時は既存セッションを失効 |
| 退塾・利用停止 | 生徒をdisabledにし既存セッションを失効 |
| 解答履歴 | 問題ID・モード・正誤・学習時間の推定値・サーバー受信時刻 |
| 重複送信 | 生徒ID＋解答イベントUUIDで重複登録しない |
| 学習時間 | 問題提示〜回答まで（表示中のみ、1問最大120秒）の**推定値**。厳密な集中時間や画面滞在時間ではない |
| 生徒画面からの送信 | 1回最大40解答のHTTPS JSON |
| 管理者用集計 | 総解答数、総正解数、推定学習時間、最終学習日時、当日・今週・今月の解答数、今月の推定学習時間（日本時間） |
| 未送信記録 | 試験版はメモリ内のみ保持。ページを閉じると未送信分は消える場合がある。正式運用前に永続キュー／再送・監視を整備する |

**未決定／正式導入前の要確認事項：** 生徒の実名表示の必要性、退塾生のデータ保有期限、講師への閲覧権限、端末を共用する場合の運用ルール、記録の保護者向け公開範囲、mikanと比較すべきレポート項目。

## D1を使うまでの準備（今は未実施）

1. Cloudflare → Storage & databases → D1 SQLite Database で専用DBを新規作成（名前候補 `up-junior-learning`）。
2. `migrations/d1-junior/0001_student_learning.sql` を**新しいD1だけ**に適用する。Render/Postgres/R2には適用しない。
3. Cloudflare Pages生徒用プロジェクトに、Binding `JUNIOR_DB`（D1）を追加。
4. 管理者専用Pages `up-junior-words-admin` にも、同じDBへ `JUNIOR_DB` を追加。
5. それぞれ設定保存後に再デプロイし、プログラムとDB接続を確認。
6. 本番デプロイ前に必ずD1のバックアップ／復元手順を確立する。

公式手順：Cloudflare Pages Functions → Bindings → D1 database。管理者サイトと生徒サイトは別プロジェクトなので、**両方**へのBindingが必要。

## 試験受入手順

1. 生徒の実データは使わず、テストID `TEST0001` を管理者側から発行。
2. 匿名・未ログインでも従来の4モードを学習できることを確認。
3. テスト生徒が仮パスワードでログイン、初回変更を求められることを確認。
4. パスワード変更後、英単語・チャンク・文節和訳・英文和訳で正誤の記録を送信。
5. 管理者ダッシュボード（今後実装）の問題数、正答率、推定時間、最終学習日時を確認。
6. iPhone・iPad・Windowsでログインして同じアカウントを使えるか確認。
7. 再送しても記録が二重にならないことを確認。
8. 管理者からパスワード再発行・利用停止を実行し、旧セッションが利用できないことを確認。
9. データの保存・バックアップ、実際の授業での負荷、学習時間計測の誤差を確認。
10. mikanと最低1か月並行運用。必須機能を代替したと判断するまでは解約しない。

## セキュリティと移行の留意点

- Cloudflare Accessのメール認証は**塾長用管理サイトだけ**。生徒70人をAccessの50ユーザー無料枠に数えない構成。
- 管理者APIは `data.verifiedAdminEmail` を必要とする。これがセットされるのは管理者Pagesの署名検証済みAccessミドルウェアのみ。生徒用Pagesでは管理者APIを通さない。
- ブラウザから受け取る正誤・時間は自己申告データなので、不正防止機構を加えるまで「監督下試験の証明」には使わない。
- アカウントの総当たり対策としてIDごとの一時ロックを実装。公開前にCloudflareのWAF/Rate Limiting、アカウントロック解除の運用を別途確認する。
- 学習記録の蓄積が停止した場合に備え、オフライン時の送信キュー・永続化と管理者向け同期失敗警告が正式導入の必須作業。
- 生徒の実名、個人情報、パスワード、Cookie、AccessトークンはGitHub・スクリーンショット・診断ログに載せない。
- 正式公開中の旧サイトと新サイトを切り替える前に、mikanの解約期限を確認する。
