# 全問音声の再開機構と保存済み音声の確認

PR #122で作成した計画を実行するための土台です。現段階のGitHub Actionsは、
オフライン検証とR2の読み取り検証だけを提供します。有料生成はコードでも無効化して
あり、このワークフローにはOpenAIのシークレットを渡していません。

## 入力

`tools/audio-full-catalog.json.gz.b64`は、元のExcelから取り出した英語と問題キーなどの
圧縮スナップショットです。日本語訳・選択肢・生徒情報・学習履歴は含みません。
Base64を戻してgzip解凍すると、`rows`に
`[mode, question_key, text, excel_row, pronunciation_review]`が入ったJSONになります。
圧縮前のSHA-256をコードで固定し、試作の原本SHAとの一致も検証します。

生成条件や試作の発音指定は既存スクリプト・試作計画から再構成します。
オフラインで9,185問・18,370本、再利用候補60本、残り18,310本を37組に分割します。

```sh
python -m pip install openpyxl==3.1.5
python tools/run_full_audio.py
python -m unittest discover -s tests -p test_run_full_audio.py
```

## GitHubから保存済み音声を確認する

1. Actions → **Prepare and audit full audio** → **Run workflow**。
2. Branchはmain、modeは**audit**、batchは**1**を選択。
3. 完了後、`full-audio-report`の`audit.json`を確認。

試作の原本計画と台帳をR2から取得し、試作60本すべてのSHA-256・バイト数・記録された
長さを照合します。続けて選んだ組の生成状況を調べます。初回なら通常は
`trial_files_verified: 60`、`not_started: 500`です。
この操作に音声生成APIの呼び出し・R2への書き込みはありません。
R2の読み取りリクエストは発生します。

## 再開機構

`run_jobs`はテスト用の擬似API・擬似R2で検証した内部実装です。
有料の実運用経路はまだ接続していません。

- 1本ごとの開始記録をR2へ条件付きで新規作成し、保存を確認してからAPIを呼びます。
- 元音声をローカルに救出用として保存し、続けてR2に保存・読み戻し検証します。
- 試作と同じ音量調整を行い、MP3と完了台帳を保存・読み戻し検証します。
- 再実行時、完了済み音声は台帳と照合してスキップします。
- 元音声だけ保存されている場合は音量調整から再開し、APIを再度呼びません。
- 開始記録だけがある場合は停止します。課金された可能性があるため、自動で開始記録を
  消したりAPIを再送したりしません。元音声の救出は個別に確認して行います。
- 保存内容の不一致・権限エラーは停止します。既存ファイルを上書きしません。
- 1回のAPIリクエスト数には上限がありますが、これは金額上限ではありません。

## 有料生成を有効にする前に残る作業

モデルの提供状況・公式料金・発音指示・予算を確認します。回数上限と使用量確認を含む
有料実行の手順を確定し、最初の少量実行でR2への実保存・再開を検証します。
全問のマニフェスト作成・公開切替・ロールバックは別の実装です。
現時点ではアプリの音声は試作30問のままです。
